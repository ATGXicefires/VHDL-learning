# 螢幕乒乓（Pong_HDMI）

在 EGO-XZ7（xc7z020clg484-1）上做的乒乓球遊戲，經板上 HDMI 接頭（J12）輸出 1024x768 @ 60 Hz。有兩種玩法：

- **2D**：經典的左右對打，單人對電腦或雙人對打。
- **3D 球桌**：從球員身後斜上方看的桌球，球有重力、會在桌上彈跳，中間有網子，照桌球規則計分。

只要一條 HDMI 線接到螢幕，不需要自製轉接板。HDMI 的驅動（ADV7511 設定、YCbCr 4:2:2 轉換、時脈轉送）直接沿用 [VGA_Screen](../VGA_Screen/README.md) 第 7 節已經上板驗證過的模組。

---

## 1. 操作

### 開關

| 開關 | 功能 |
|---|---|
| SW7 | 撥上 = 運作，撥下 = 重置 |
| SW0 | 0 = 2D，1 = 3D 球桌 |
| SW1 | 2D 時：0 = 單人對電腦，1 = 雙人（3D 固定對電腦） |
| SW2 | 電腦難度：0 = 簡單，1 = 困難 |

切換 2D / 3D 時，沒在玩的那一邊會凍結，切回來可以接著玩。

### 按鈕

| 按鈕 | 2D | 3D |
|---|---|---|
| BTNC | 發球 / 暫停 / 比賽結束後開新局 | 同左 |
| BTNU / BTND | 左球拍（P1）上 / 下 | 球拍上 / 下 |
| BTNR / BTNL | 雙人時右球拍（P2）上 / 下 | 球拍右 / 左 |

雙人模式時 P1 用上下鍵、P2 用左右鍵（右 = 上、左 = 下）。按住方向鍵會越來越快：輕點可以微調，按住可以趕到遠處。

### LED

| LED | 意義 |
|---|---|
| LD0 | MMCM 已鎖定（像素時脈穩定） |
| LD1 | 3D 模式 |
| LD2 | 2D 雙人模式 |
| LD3 | 暫停中 |
| LD4 | 等待發球 |
| LD5 | 比賽結束 |
| LD6 | ADV7511 設定完成（I2C 都有 ACK） |
| LD7 | 偵測到 HDMI 螢幕（HPD） |

## 2. 規則

- 先得 7 分獲勝，勝方的比分會閃爍；按 BTNC 開新局。
- **得分方發下一球**（和 LED_PingPong 一樣）。輪到你發球時球會黏在你的球拍前，按 BTNC 發球；輪到電腦時它約 0.8 秒後自己發。
- 比賽中按 BTNC 暫停，球會閃爍；再按一次繼續。剛發球的 0.25 秒內按 BTNC 不算暫停，免得電腦發球的同時按到。
- 每得一分畫面停約 1 秒。

### 2D

- 左邊橘色球拍是 P1，右邊青色是 P2 或電腦；比分顏色和球拍相同。
- 球打在球拍中間會直直回去，打在拍緣角度最大。每次回球球速加快一點，最快每 frame 16 像素。
- 電腦只在球朝它飛來時追球（簡單模式要等球過半場），有速度上限，斜線快球會漏接。困難模式會故意用拍緣接球打出角度。

### 3D 球桌

- 前面半透明的圓拍是你的球拍，網子對面的紅色球拍是電腦。
- **判斷高低遠近**：桌面上有球的影子，影子在哪裡，球就在那個位置的正上方；球和影子離得越遠，球越高。
- 回球要先在對方半場彈一次。以下情況是**你失分**：
  - 撞網。
  - 落在自己這邊。
  - 出界，包括飛出桌子兩側或太長。
  - 沒接到、讓球在自己半場彈兩次。
  電腦犯同樣的錯就是你得分。
- 球彈起來飛到你面前時，多半在桌面上方一點，所以球拍大多只要左右移；高球或低球再上下調整。
- **回球方向**：
  - 打在拍子中心，球回到桌子中線附近。
  - 打在拍緣，或擊球時球拍正在左右移動，球就斜向邊線，太偏會出界。
  - 打在拍子上半部球比較長，太長也會出界。
- 每次你回球，球速都會快一級（共 8 級），得分後回到最慢。
- 發球簡化成直接打到對方半場（真的規則要先彈自己這邊），落點跟著你的球拍左右位置。
- 得分時畫面外圈閃綠（你得分）或閃紅（電腦得分）。

## 3. 接線

1. HDMI 線接板上的 J12（HDMI OUT）到螢幕。
2. SW8 全部撥 ON 再上電（JTAG 才找得到 FPGA）。
3. 燒錄後 LD6、LD7 都亮就表示 HDMI 晶片設定好、螢幕也接上了。

畫面有雜點或閃爍時，把 `pong_top` 的 generic `CLK_INVERT` 改成 `true` 重新產生 bitstream（VGA_Screen 在 1280x1024 都不需要，1024x768 應該也不用）。

## 5. 模擬、建置與燒錄

以下指令都在專案根目錄執行（Vivado 路徑 `D:\Vivado\2026.1\Vivado\bin\vivado.bat`）。

```
python tools/sim.py game
python tools/sim.py presets
vivado -mode batch -source tools/create_project.tcl
vivado -mode batch -source tools/build.tcl
vivado -mode batch -source tools/program.tcl
```

- `game`：三局機器人對打，檢查球和球拍不出界、比分只會加 1、7 分結束、BTNC 開新局，通過時印 `pong_game_tb PASS`，並在 `sim_out/` 畫出 `pong2d_play.gif`、`pong3d_play.gif`。加 `HARD2D=1 HARD3D=1` 測困難模式。
- `presets`：擷取幾個情境的完整畫面到 `sim_out/*.png`（每張約 1 分鐘）；`python tools/sim.py sheet <名稱...>` 拼成一張對照圖。
- bitstream 在 `Pong_HDMI.runs/impl_1/pong_top.bit`，時序與資源報告在 `sim_out/timing.rpt`、`utilization.rpt`。
- 按下 S12 會清掉 PL 的設定，重新燒錄即可。

機器人只看得到約 0.2 秒前的球（和真人反應時間差不多）。3D 的機器人會像真人一樣看弧線推算球到面前的位置，並且每球挑拍子上偏一點的地方打，回出角度。目前的難度在機器人對打下的結果：

| | 簡單 | 困難 |
|---|---|---|
| 2D 單人（玩家 : 電腦） | 7 : 3 | 5 : 7 |
| 3D 球桌（玩家 : 電腦） | 7 : 3 | 4 : 7 |

## 6. 設計重點

### 遊戲邏輯只在垂直遮沒期間更新

`frame_tick`（最後一條可視掃描線結束後）觸發一步，`*_ctrl` 用 ph = 1..7 依序算完：球拍 → 球前進 → 反彈（2D 是上下牆，3D 是網子和桌面）→ 擊球 → 得分。整個 frame 狀態都不變，畫面不會撕裂，各步也可以用前一步的結果（例如擊球判斷用的是已經反彈過的位置）。

擊球不是看「球和球拍有沒有重疊」，而是看這一步球的正面有沒有**穿過**球拍那一面：球速快時一步會移動超過球拍厚度，只看重疊可能直接穿過去。

### 3D 透視不用除法

透視投影是 `螢幕 = (512 + X·s, HZ_Y + Y·s)`，`s(z) = 768 / (768 + z)`。眼睛比桌面高 `TBL_Y`，視平線 `HZ_Y` 在螢幕上方外面，所以看起來是從斜上方往下看。`s` 只跟深度有關，所以在 `pong_pkg` 裡事先算成 256 格的表（`SCALE`，elaboration 時由 constant function 算好，不需要另外的產生器）。

每個 frame 只有球和兩支球拍會動，它們的投影（球心、半徑、影子位置、球拍中心）在 `pong3d_draw` 的「每幀值」暫存器裡算好；掃描像素時只做比較：

- **桌面**：桌面上第 y 列的縮放是 `(y − HZ_Y) / TBL_Y`，那一列桌面的半寬是 `TW` 乘上它。所以「在桌面上」就是 `|dx|·TBL_Y < TW·(y − HZ_Y)`，兩邊都只是乘常數，邊線就是兩者差距很小的地方。
- **網子、端線、桌子前緣**：在固定深度，畫面上就是固定的幾列（`Y_NET` 等常數），網格用 x、y 的低位元畫。網眼是透明的，看得到後面的球。
- **誰蓋過誰**：球在網子前（玩家這側）時球蓋過網子，否則網子蓋過球。
- **影子**：畫在桌面高度 `(bx, TBL_Y, bz)` 的扁橢圓 `dx² + 4dy² < r²`，只在桌面上才畫。
- **圓形球拍和球**：比較到圓心距離的平方；球再比較到「左上方高光點」的距離，分 4 級明暗。

### 擊球用落點反推速度

擊球時不直接給速度，而是先決定**落點**（玩家看擊球點和球拍速度，電腦用亂數），再反推速度：

- 飛到落點要 `T` 個 frame，`T` 依速度級查表。
- 水平速度 `v = (落點 − 現在位置) / T`，除以 `T` 換成乘上常數 `RECIP = 4096 / T` 再右移 12 位。
- 垂直速度再扣掉重力的修正 `G·(T − 1) / 2`，球就會剛好在 `T` 個 frame 後落在那一點。
- `RECIP` 和修正量都是 constant function 算好的 8 格表，所以整個 3D 遊戲邏輯不需要除法器。

好處是落點可以由玩家控制（打在拍緣就斜、太偏就出界），弧線也一定會落到該落的地方。最快的一級還是要飛 30 個 frame，再快弧線太平，從低處回球幾乎都會掛網。

### 將來接鍵盤

按鈕在 `pong_top` 先轉成控制向量 `ctrl`（位元定義在 `pong_pkg`：發球、P1 上下左右、P2 上下），遊戲邏輯只看這個向量。要接 PS/2 鍵盤或 USB 轉序列模組時，只要加一個把按鍵解成同樣格式的模組，在 `pong_top` 和按鈕的 `ctrl` OR 起來即可，遊戲本體不用改。

EGO-XZ7 的 USB 接頭接在 Zynq 的 PS（ARM）端，PL 讀不到，所以一般 USB 鍵盤不能直接插板子；可行的做法是 PS/2 鍵盤（或支援 PS/2 轉接頭的 USB 鍵盤）接 JA2 排針，或用 CH9350 之類的 USB 轉序列模組。
